# GNN–BERT for Understanding Context from Music: Results and Analysis

**CSE425 / EEE474 / CSE715 — Supervised Neural Network Project**

All figures in this report are read directly from `results/metrics/*.json`,
generated by the scripts listed in Appendix A. Two tuning iterations are
reported side by side throughout: **Iteration 1** (2026-09-03) and
**Iteration 2** (2026-09-09); their scope is defined in §2.3.

## Abstract

This report presents results for a four-task pipeline that combines a BERT
text encoder with a graph neural network (GNN) audio encoder for
context-aware music understanding. **Task 1** fine-tunes BERT to predict
MusicCaps caption tags; after correcting three sources of under-reporting
(an 8-epoch training cap, a lopsided official train/eval split, and disabled
positive-class reweighting), the leakage-free variant reaches **0.525** test
Macro-F1, modestly ahead of a TF-IDF baseline (0.512). **Task 2** compares a
GNN against a CNN on GTZAN genre classification; two rounds of
graph-construction tuning — a similarity-edge density correction, a switch
from GraphSAGE to graph attention (GAT), and a move to beat-synchronous
segmentation — raise GNN test accuracy from 76.0% to **77.3%**, but the CNN
baseline remains stronger throughout (83.3%). **Task 3** fuses the GNN and
BERT branches on MagnaTagATune across four ablation modes; concatenation
fusion (0.448 Macro-F1) and cross-attention fusion (0.430) are close, and
their relative ranking **reverses** between the two tuning iterations —
flagged here as a single-seed result that needs confirmation, not a settled
conclusion. **Task 4** trains a contrastive dual encoder for cross-modal
retrieval; because Task 4 reuses Task 3's cached graphs, the same
segmentation change that helped Task 3 mildly *regresses* Task 4's retrieval
metrics (Recall@10 11.4% → 10.7%), illustrating a coupling between the two
tasks that is not free to resolve independently. A recurring diagnostic
finding — persistent node-embedding collinearity (mean pairwise cosine
similarity ≈ 0.98, `S_graph` ≈ 1.0 at the configured threshold) that none of
the three architectural interventions reduced — is identified as the
project's primary open problem, and is argued to be a property of the pooled
fusion representation rather than of graph construction.

## 1. Introduction

The project studies whether a hybrid text–graph architecture — a pretrained
BERT encoder for natural-language context, fused with a GNN encoder over
music-structure graphs — improves on unimodal baselines for four
progressively harder tasks:

1. **Task 1 (Easy).** Fine-tune BERT to predict music tags from natural-
   language captions, establishing the text encoder used everywhere else.
2. **Task 2 (Medium).** Compare a GNN over segment graphs against a CNN over
   mel-spectrograms for genre classification, testing whether graph
   structure helps when audio is represented natively rather than as a
   fixed-size image.
3. **Task 3 (Hard).** Fuse the GNN and BERT branches for multi-label tag
   prediction and compare four fusion mechanisms, isolating how much the
   audio and text modalities each contribute.
4. **Task 4 (Advanced).** Train a contrastive dual encoder (InfoNCE) to align
   audio-graph and caption embeddings in a shared space, and evaluate
   cross-modal retrieval and zero-shot tagging.

Sections 3–6 report each task in turn. Section 7 synthesizes cross-task
findings, Section 8 states the project's limitations plainly, and Section 9
recommends concrete next steps. Appendix A gives exact reproduction commands;
Appendix B is a dated log of issues found and fixed during development.

## 2. Experimental Setup

### 2.1 Hardware and software

All experiments ran on a single NVIDIA GeForce RTX 5090 with PyTorch
2.11.0+cu128, PyTorch Geometric for graph operations, and Hugging Face
Transformers for BERT. Mixed-precision (AMP) training is used throughout.

### 2.2 Shared conventions

- **Warm-starting.** Tasks 3 and 4 initialize their text branch from Task 1's
  converged checkpoint (`results/checkpoints/task1_bert_best.pt`); all three
  tasks are configured to use the same base model name so this load succeeds.
- **Threshold tuning.** Per-tag decision thresholds are tuned on the
  validation split only (grid search, step 0.05) and then frozen for test-set
  evaluation, avoiding test-set leakage into threshold selection.
- **Reporting convention.** Every number in this report is traceable to a
  specific file under `results/metrics/`; file names are given alongside each
  table.

### 2.3 Two tuning iterations

**Iteration 1 (2026-09-03).** Addressed under-training and data issues:
training epochs raised (8→30 for Task 1, 15→20 for Task 3); Task 1's split
moved off the lopsided official `is_audioset_eval` partition to a seeded
~72/13/15 split by `ytid`; positive-class reweighting (`pos_weight`) enabled
for Task 1; Task 3/4 text rebuilt from MagnaTagATune's own non-label
descriptor tags instead of bare metadata; Task 3 audio window widened from
10 s to the full ~29 s clip (10→19 nodes/graph).

**Iteration 2 (2026-09-09).** Addressed a graph-construction concern raised
during review: GTZAN similarity graphs measured **92.8% dense** (mean degree
9.28 of a possible 10), meaning a node's neighborhood was nearly the whole
graph — likely blunting any GNN's ability to use structure. Three changes
were applied together and the full pipeline re-run end to end:

- (a) **Similarity-edge density correction** — `sim_threshold` 0.8→0.95,
  `max_sim_neighbors` 8/6→3 (Tasks 2 and 3).
- (b) **Convolution type** — GraphSAGE → graph attention (GAT), which learns
  per-neighbor attention weights instead of a uniform mean; the project
  specification permits either (Sec. 4.2).
- (c) **Segmentation** — fixed-length windows → beat-synchronous segments,
  which the specification also explicitly permits (Sec. 3) and which
  produces genuinely variable-length graphs instead of a uniform node count
  per clip.

These three changes are reported together because they were applied and
evaluated as one combined configuration, not because their individual
contributions are assumed equal; where the evidence supports attributing an
effect to one specific change, this is stated in the relevant task section.

## 3. Task 1 — BERT Baseline for Music-Tag Understanding

### 3.1 Data and setup

MusicCaps captions are used to predict the top-50 most frequent tag
("aspect") labels. The split is a seeded, stratified-by-`ytid` ~72/13/15
partition (`use_official_eval_split: false`) rather than the official
`is_audioset_eval` flag, which marks 53% of usable clips as eval and starves
training to only ~2,200 clips.

| Split | Clips |
| --- | --- |
| Train | 3,607 |
| Validation | 637 |
| Test | 752 |

Positive-class reweighting (`pos_weight`, clipped at 20, mean 16.6) is
enabled to counter label sparsity across 50 tags.

### 3.2 The leakage problem

Exploratory analysis (`notebooks/eda.ipynb`, §1) found that **62%** of a
clip's true tags occur verbatim as substrings in its own caption, making the
unmasked caption→tag task substantially a string-matching exercise. Both
settings are reported: `mask_aspect_spans: true` (masked, leakage-free —
verbatim tag spans deleted from the input text) is treated as the headline
result, and the unmasked setting is reported only to quantify how much of
the score is attributable to leakage.

### 3.3 Results

**Masked (leakage-free), test set, 752 clips, 50 tags, best epoch 26/29:**

| Model | Macro-F1 | Micro-F1 | AUC-PR |
| --- | --- | --- | --- |
| Random baseline | 0.063 | 0.089 | 0.061 |
| Majority-class baseline | 0.018 | 0.175 | 0.061 |
| TF-IDF + logistic regression | 0.512 | 0.561 | 0.534 |
| BERT, default threshold (0.5) | 0.511 | 0.540 | 0.533 |
| **BERT, tuned thresholds** | **0.525** | 0.557 | 0.533 |

With leakage removed, BERT edges the non-neural TF-IDF baseline by +0.013
Macro-F1. Because the task remains largely lexical even without verbatim
spans, this margin is modest — but with adequate training data and
`pos_weight` enabled, it is a real, positive margin rather than the negative
one seen before Iteration 1's fixes (see Appendix B, item 1).

**Effect of leakage** (unmasked run, best epoch 29/30):

| Model, tuned thresholds | Masked (headline) | Unmasked (with leakage) | Δ |
| --- | --- | --- | --- |
| BERT Macro-F1 | 0.525 | 0.720 | +0.195 |
| BERT AUC-PR | 0.533 | 0.765 | +0.232 |
| TF-IDF Macro-F1 | 0.512 | 0.686 | +0.174 |

BERT stays ahead of TF-IDF in every column of both settings, and the margin
is decisive (+0.034 Macro-F1) only once leakage is present — the pretrained
encoder's advantage over string statistics is small on this proxy task, and
most of it is explained by matching verbatim tag mentions.

At the per-tag level (unmasked), the easiest tags are recording/production
descriptors that are near-guaranteed literal substrings (`low quality` F1
0.98, `mono` 0.95, `noisy` 0.92); the hardest are subjective mood/instrument
words that resist simple string matching (`spirited` 0.27, `loud` 0.36,
`upbeat` 0.43).

**Deliverables:** `task1_f1_curves.png`, `task1_per_tag_f1.png`, five
`task1_attention_*.png` `[CLS]`-attention heatmaps, `task1_examples.json`,
`task1_mask_comparison.json`, and per-variant copies under
`results/task1_variants/{unmasked,masked}/`.

## 4. Task 2 — Graph Neural Network vs. CNN Baseline (GTZAN)

### 4.1 Data and setup

GTZAN (10 genres, 1,000 tracks, 30 s clips) is split 699/150/150
(train/val/test) via stratified random sampling; GTZAN ships no artist
metadata, so an artist-disjoint split is not possible — a dataset
limitation, not an evaluation oversight. Each track is represented as a
segment graph with 83-dimensional node features (MFCC, chroma, and spectral
statistics).

Under **Iteration 1**, segments were fixed 5 s windows (50% overlap),
producing a uniform 11 nodes per graph, and similarity edges used
`sim_threshold: 0.8`. Under **Iteration 2**, segmentation switched to
beat-synchronous windows (`beats_per_segment: 8`, `min_segments: 4`) and the
similarity threshold was tightened to 0.95 (`max_sim_neighbors: 3`),
producing genuinely variable-length graphs: train mean 8.23 nodes (range
5–15), validation mean 7.89 (5–12), test mean 8.13 (5–14), mean degree ≈ 4.4
(`results/metrics/task2_graph_stats.json`).

### 4.2 Results

| Model | Iteration | Params | Best epoch | Accuracy | Macro-F1 | Top-3 acc. |
| --- | --- | --- | --- | --- | --- | --- |
| GraphSAGE, density-corrected, fixed-window graphs | 1 | 105,738 | 14 | 76.0% | 0.752 | 91.3% |
| **GAT, density-corrected, beat-synchronous graphs** | **2** | **63,114** | **22** | **77.3%** | **0.772** | **92.0%** |
| CNN mel-spectrogram baseline (unverified, see note) | 1 | 1,206,826 | 54 | 82.0% | 0.822 | 96.0% |
| CNN mel-spectrogram baseline | 2 | 1,206,826 | 56 | 83.3% | 0.836 | 96.0% |

*(Provenance note. `results/metrics/task2_results.json` stores one entry per
model key and is overwritten in place on each training run, so it only ever
holds the **most recent** result for a given key. The Iteration 2 pipeline
retrained `gnn_gat` and `cnn_melspec` but not `gnn_sage`; consequently the
GraphSAGE row above is read from a live file, but reflects GraphSAGE **with
the Iteration 2 similarity-density correction already applied** (i.e. an
intermediate configuration), not the original pre-correction baseline. Both
the original GraphSAGE baseline (75.3% accuracy / 0.750 Macro-F1, under
`sim_threshold: 0.8`) and the Iteration 1 CNN row shown above (82.0%) are
carried over from the prior write-up and can no longer be independently
re-verified against a live results file, since both underlying entries have
since been overwritten by later training runs. They are shown for continuity
with the project's development history but should not be treated as
re-confirmed. Every other number in this report was cross-checked against
its source file at the time of writing.)*

### 4.3 Discussion

Switching GraphSAGE→GAT and fixed-window→beat-synchronous segmentation
raises GNN test accuracy by **+1.3 points** and Macro-F1 by **+0.020** over
the density-corrected GraphSAGE baseline, with **fewer** parameters — GAT's
per-head projections are more parameter-efficient here than GraphSAGE's
aggregation. (The density correction itself accounts for a further, smaller
prior gain, from 75.3% to 76.0%, per the unverifiable earlier run noted
above.) This is the strongest GNN configuration found in this project, and
it is the first configuration in which the graphs genuinely exercise
variable-length structure rather than a fixed node count. Even so, the
**CNN baseline remains ahead by roughly 6 points of accuracy** in both
iterations. GTZAN is small (1,000 tracks) and well documented in the
literature as rewarding capacity and regularization tuning on raw
mel-spectrograms; giving the GNN real structural variation did not close
this gap. Confusion matrices (`task2_confusion_gnn_gat.png`,
`task2_confusion_cnn_melspec.png`) show both models' errors concentrated on
the same classically difficult GTZAN genre pairs (rock/country,
disco/reggae/rock).

**Deliverables:** `task2_curves.png`, both confusion matrices, 20 example
graph samples under `data/processed/graph_samples/`.

## 5. Task 3 — GNN–BERT Fusion for Multi-Context Understanding

### 5.1 Data preparation

21,111 MagnaTagATune clips are indexed against the top-50 tag vocabulary.
Text uses the `descriptive_tags` mode: each clip's own tags that fall
outside the 50-tag label set (stem-deduplicated against the labels) plus
title/artist, falling back to bare `Artist/Album/Title` metadata when no
such descriptor tags exist (~39% of clips get real descriptors). Under
Iteration 2, audio is segmented into beat-synchronous windows over the full
~29 s clip (Iteration 1 used fixed 3 s windows at 50% overlap, producing a
uniform 19 nodes/graph). Three clips are skipped at graph-build time — clip
IDs 35644, 55753, and 57881, all in the train split — because the
corresponding MP3 files in the official MagnaTagATune distribution are zero
bytes (a known defect of that archive, documented in
`results/metrics/task3_skipped_clips.json`). This yields **21,108 paired
examples**, split train 15,247 / val 1,529 / test 4,332; since all three
skips are train-side, validation and test metrics are unaffected.

Two software issues were found and fixed while preparing this task; both are
documented in full in Appendix B, since they are development history rather
than results. In brief: (i) the MagnaTagATune audio archive had been
downloaded but never extracted, and (ii) `src/analyze_fusion.py` computed
the graph-coherence diagnostic incorrectly on GPU runs due to an in-place
tensor-mutation bug in a PyTorch Geometric call; both were fixed before the
coherence numbers below were produced.

### 5.2 Ablation results

Four fusion mechanisms are compared: `bert_only` (text branch alone,
retrained from the Task 1 checkpoint), `gnn_only` (graph branch alone),
`concat` (feature concatenation), and `cross_attention` (the specification's
recommended mechanism, in which text attends to graph node embeddings). All
figures below are test-set, tuned-threshold results from
`results/metrics/task3_results.json`.

**Iteration 2 (current, GAT + beat-synchronous graphs):**

| Mode | Representation | Macro-F1 | Micro-F1 | AUC-PR | Best epoch |
| --- | --- | --- | --- | --- | --- |
| `bert_only` | `t` | 0.367 | 0.412 | 0.365 | 17/20 |
| `gnn_only` | `g` | 0.423 | 0.464 | 0.407 | 14/18 |
| **`concat`** | `[g ; t]` | **0.448** | 0.480 | **0.450** | 7/11 |
| `cross_attention` | `[g ; A·H_text]` | 0.430 | **0.482** | 0.439 | 10/14 |

**Iteration 1 (GraphSAGE + fixed-window graphs), for comparison:**

| Mode | Macro-F1 | Micro-F1 | AUC-PR |
| --- | --- | --- | --- |
| `bert_only` | 0.367 | 0.412 | 0.365 |
| `gnn_only` | 0.422 | 0.447 | 0.401 |
| `concat` | 0.440 | 0.483 | 0.450 |
| `cross_attention` | 0.443 | 0.470 | 0.447 |

### 5.3 Discussion

Two findings stand out. First, **all fusion modes clearly outperform
`bert_only` alone** in both iterations, confirming that the graph branch
contributes real, non-redundant signal beyond what the text branch alone
captures. Second, **the ranking between `concat` and `cross_attention`
reverses between iterations**: `cross_attention` led under fixed-window
GraphSAGE graphs (0.443 vs. 0.440), while `concat` leads under beat-
synchronous GAT graphs (0.448 vs. 0.430). `bert_only` is identical to three
decimal places across both iterations, as expected — segmentation and
convolution changes do not touch the text branch — which serves as a useful
sanity check that the two ablation runs are otherwise comparable. `gnn_only`
moves by only +0.001, essentially flat.

Because the `concat`/`cross_attention` gap (0.018 Macro-F1) is of the same
order of magnitude as the swing that produced the reversal, and both
Iteration 2 numbers come from a **single training seed**, this ranking is
reported as a provisional finding rather than a settled conclusion.
`config.yaml`'s `task3.model.mode` has been set to `concat` to reflect the
current best result, but a multi-seed confirmation (2–3 seeds per mode) is
recommended before this is treated as final (see §9).

### 5.4 Graph coherence diagnostic

`src/diagnose_coherence.py` measures `S_graph`, the fraction of graph edges
whose endpoint node embeddings have cosine similarity above a configured
threshold `coherence_tau` (0.5 by default) — intended as a proxy for how
much the GNN's learned representation reflects graph structure versus
collapsing every node to a similar vector.

| Metric | Iteration 1 | Iteration 2 |
| --- | --- | --- |
| Edge-cosine mean | 0.95 | 0.981 |
| Edge-cosine p50 | 0.97 | 0.990 |
| Edge-cosine p90 | 0.99 | 0.999 |
| `S_graph` at τ = 0.5 | ≈ 1.0 | 1.0000 |

In both iterations, essentially 100% of edges exceed τ = 0.5, so `S_graph`
is pinned near its maximum and cannot discriminate structure quality at the
configured threshold; the diagnostic only begins to separate graphs once τ
is raised toward 0.95–0.99. **None of the three Iteration 2 changes —
sparser graphs, attention-based aggregation, or variable segmentation —
reduced this saturation; if anything, the edge-cosine distribution shifted
slightly higher.** This is read as evidence that the saturation is a
property of the pooled fusion representation itself (over-smoothing that
occurs downstream of, or during, pooling) rather than an artifact of graph
construction, and is discussed further as an open problem in §7 and §9.

### 5.5 Qualitative analysis

Three case studies were regenerated on the Iteration 2 (beat-synchronous)
graphs — `task3_case_1_38334.png`, `_2_5671.png`, `_3_45347.png` — each
showing the model's greedy dominant-path walk through the segment graph, its

vary meaningfully across cases (12, 20, and 8 nodes respectively), in

## 6. Task 4 — Contrastive Cross-Modal Retrieval

### 6.1 Setup

Task 4 reuses Task 3's paired dataset directly (no separate download);
consequently, it inherits whichever segmentation scheme Task 3's cached
graphs were built with. 4,332 test pairs are evaluated with a symmetric
InfoNCE loss, temperature τ = 0.07, batch size 128 (127 in-batch negatives
per step), best epoch 30/30. Text uses the same descriptor-tag rebuild as
Task 3.

### 6.2 Retrieval results

Full 4,332-candidate gallery evaluation (not in-batch), from
`results/metrics/task4_results.json`:

| --- | --- | --- | --- | --- | --- |
| audio → caption | 1.3% | 6.9% | 11.1% | 200 | 0.046 |
| caption → audio | 2.1% | 7.8% | 11.4% | 194 | 0.054 |

**Iteration 2 (GAT, beat-synchronous graphs):**

| caption → audio | 2.0% | 7.1% | 10.7% | 200 | 0.052 |

### 6.3 Zero-shot tagging

Top-3 zero-shot tagging (threshold-free), comparing the trained graph
encoder against a text-only control that scores the same prompts against
caption embeddings:

| Query embedding | Iter. 1 Macro-F1 | Iter. 1 AUC-PR | Iter. 2 Macro-F1 | Iter. 2 AUC-PR |
| --- | --- | --- | --- | --- |
| Graph (audio) | 0.084 | 0.087 | 0.084 | 0.086 |
| Caption (text-only control) | 0.080 | 0.079 | 0.087 | 0.086 |

### 6.4 Discussion

**Iteration 2's segmentation change is a mild regression for Task 4.**
Recall@5 and Recall@10 both drop by roughly 0.5–0.7 points in each
direction; Recall@1 and MRR are essentially unchanged. On the zero-shot
diagnostic, the graph-side score is flat (0.084 in both iterations), but the
text-only control improves to 0.087 — so the graph embedding no longer
demonstrates a clear advantage over the text-only control, as it did under
Iteration 1. This is the one Tier-2 change that did not help, in contrast to
its positive or mixed effects on Tasks 2 and 3.

A structural reason this is hard to resolve independently: **Task 4 has no
segmentation setting of its own** — it consumes Task 3's cached fusion file
(`data/processed/fusion/task3_fusion_*.pt`) directly, so the beat-
synchronous graphs that helped Task 3's `concat`/`gnn_only` modes are the
same graphs feeding Task 4. Reverting Task 4 to fixed-window segmentation
while keeping Task 3 on beat-sync is not possible without decoupling their
audio caches — currently, the two tasks' segmentation choice is a shared,
not independently tunable, setting.

Two hypotheses are proposed for the regression, neither yet tested: (i) the
shift from a fixed 3 s window to beat-count-based segmentation may alter the
node-count distribution in a way that interacts unfavorably with in-batch
negative sampling, or (ii) beat-tracking may simply be a weaker segmentation
signal than fixed windows specifically for MagnaTagATune's ~29 s clips.

Independent of segmentation, both iterations confirm an earlier finding: the
Iteration 1 text rebuild (descriptor tags rather than bare metadata)
roughly doubled retrieval over a pre-Iteration-1 metadata-only baseline
(caption→audio R@5 5.0%→7.8%, R@10 7.8%→11.4%, median rank 312→194) and
flipped the zero-shot diagnostic from tied to graph-favoring. Absolute
retrieval performance remains modest in every configuration tried — a
consequence of MagnaTagATune's text being closer to structured metadata than
to a genuine caption, which limits how discriminative the text side of the
contrastive objective can be.

## 7. Cross-Task Synthesis

| Task | Iteration 2 headline | Δ vs. Iteration 1 | Interpretation |
| --- | --- | --- | --- |
| 1 | Masked BERT 0.525 Macro-F1 vs. TF-IDF 0.512 | — (single iteration) | Leakage-free BERT edges TF-IDF by a small but positive margin |
| 2 | GNN 77.3% acc.; CNN 83.3% | GNN +1.3 pts acc. | GNN improves and finally uses variable-length graphs, but CNN still wins |
| 3 | `concat` 0.448 (best); `cross_attention` 0.430 | Ranking of best mode **reverses** | Fusion still beats text-only; which mechanism wins is seed-sensitive |
| 4 | caption→audio R@10 10.7% | −0.7 pts | The one Tier-2 change with a net negative effect |

Two findings generalize across tasks:

**Graph over-smoothing is unresolved and likely architectural.** Three
independent interventions — sparser similarity edges, attention-based
aggregation (GAT), and variable-length segmentation — were each motivated by
a plausible hypothesis about why node embeddings might be collapsing
together, and none reduced the coherence-saturation metric (§5.4). This
consistency across three structurally different fixes is itself evidence:
the problem most likely sits in the pooling/fusion step downstream of the
GNN rather than in how the input graphs are built.

**Tasks 3 and 4 are coupled through a shared graph cache, creating a genuine
trade-off.** The same segmentation change that measurably helped two of
Task 3's four fusion modes measurably hurt Task 4's retrieval metrics. This
is not a bug to be fixed by picking better hyperparameters; it reflects that
Tasks 3 and 4 currently share one audio-processing configuration when their
optimal configurations may differ.

Finally, the choice of MagnaTagATune over MusicCaps for Tasks 3–4 (Appendix
B, item 6) is a consistent lens on both Task 3's ablation ordering and
Task 4's retrieval ceiling: in both tasks, the audio/graph branch is the
stronger modality and the metadata-derived text branch is the limiting one.

## 8. Limitations

- **GTZAN has no artist metadata**, so Task 2's train/val/test split is
  stratified-random rather than artist-disjoint; scores may be mildly
  optimistic relative to an artist-disjoint evaluation.
- **MagnaTagATune has no captions.** Its synthesized descriptor-tag text is
  a genuine, non-leaking signal but is weaker than natural-language
  captions, and this bounds both Task 3's text branch and Task 4's
  contrastive alignment quality.
- **MusicCaps audio is largely inaccessible in this environment** (165 of
  5,521 clips, 3.0%), so Tasks 3 and 4's headline numbers describe
  MagnaTagATune, not the specification's first-choice dataset; this is a
  deliberate, documented substitution rather than an oversight (Appendix B,
  item 6).
- **The Task 3 ablation ranking (§5.3) rests on a single training seed** per
  mode; the `concat`/`cross_attention` reversal between iterations is of a
  similar magnitude to the effect being measured and should be treated as
  provisional.
- **Task 4's beat-synchronous regression is undiagnosed** (§6.4): two
  hypotheses are proposed but neither has been tested.
- **Graph coherence saturation is unresolved** (§5.4, §7): the diagnostic
  indicates the problem but the three interventions attempted did not
  address its root cause.

## 9. Recommendations for Future Work

1. **Multi-seed replication of the Task 3 ablation**, at minimum for
   `concat` and `cross_attention` under Iteration 2's configuration, to
   confirm whether the observed ranking reversal is a real interaction
   between fusion mechanism and segmentation scheme or single-seed noise.
2. **Decouple Task 3 and Task 4's audio/graph caches** so each task's
   segmentation scheme can be tuned independently, removing the trade-off
   documented in §7.
3. **Address graph over-smoothing directly**, since graph-construction
   changes have been exhausted without effect: candidates include embedding
   dropout or noise injection before pooling, and an explicit decorrelation
   or diversity regularizer on node embeddings.
4. **Diagnose the Task 4 regression** by testing the two hypotheses in §6.4
   in isolation — e.g., comparing node-count distributions and in-batch
   negative composition under both segmentation schemes on a matched subset.
5. **Revisit `coherence_tau`** (currently 0.5) — raise it toward 0.95–0.99,
   or report the full edge-cosine distribution rather than a single
   thresholded scalar, in any future write-up that cites `S_graph`.
6. If MusicCaps audio access improves in this environment, re-run Tasks 3
   and 4 on genuine captions to isolate how much of the current text-branch
   ceiling is a MagnaTagATune-specific limitation versus a property of the
   fusion/contrastive architecture itself.

## 10. Conclusion

Across two tuning iterations, the project's central architectural question —
does adding a graph-structured audio encoder improve on strong unimodal
baselines — receives a qualified yes for the fusion task (Task 3, where
every fusion mode beats text-only) and a qualified no for the pure
classification task (Task 2, where a CNN baseline remains ahead throughout).
The Iteration 2 tuning pass, prompted by a legitimate concern about
graph density, produced genuine improvements on Task 2 and a mixed,
seed-sensitive result on Task 3, but a small regression on Task 4 — a result
that is reported here in full rather than selectively, together with the
still-open graph-coherence problem that motivated the tuning pass in the
first place but was not resolved by it.
